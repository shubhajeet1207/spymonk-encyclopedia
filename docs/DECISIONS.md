# SpyMonk Encyclopedia — Architecture & Design Decisions

This document records the decisions behind the current system and the intended evidence-validation evolution. Status is explicit so the documentation does not overstate implemented behavior.

| ID | Decision | Status | Rationale and consequence |
| --- | --- | --- | --- |
| ADR-001 | Build a local-first archive. | Implemented | ChromaDB, JSON topic files, and source snapshots are stored under the project. This makes retrieval inspectable and keeps the primary corpus under user control. |
| ADR-002 | Use React for the user interface and FastAPI for the local HTTP API. | Implemented | React/Vite provides a responsive, separate frontend while FastAPI exposes the existing Python research, query, and ingestion workflows. Long research runs as a background job (ADR-018), not inside the request. |
| ADR-003 | Use RAG, not a free-form chat model. | Implemented | Answer generation receives only retrieved excerpts and an explicit no-prior-knowledge prompt. This reduces unsupported answers but cannot guarantee that an LLM follows instructions perfectly. |
| ADR-004 | Require verbatim quote checks for web claims. | Implemented | Candidate quotes are normalized and matched against extracted source text before indexing. This prevents a model-only claim from entering the archive, although it only validates attribution to that source. |
| ADR-005 | Separate readable audit memory from the retrieval index. | Implemented | JSON audit files are the source of truth for web research; Chroma is derived from them and from stored PDFs. A save writes the audit first, then the index, and records `index_state` (`pending`, `indexed`, `stale`). `python -m backend.core.reindex` (or the Rebuild button) recreates the index from audits and PDFs. Moving audits into SQLite for transactional writes is a deferred decision. |
| ADR-006 | Use deterministic document IDs. | Implemented | A PDF's identity is the SHA-256 of its bytes and chunks are numbered per document, so re-uploading or re-ingesting the same file updates rather than duplicates it; identical uploads are rejected as duplicates. A web claim's ID is a hash of its canonical topic and normalized text, so refreshes update claims in place. Repeated chunk text within one document is indexed once. |
| ADR-007 | Use public-URL and redirect checks with bounded fetches. | Implemented | Each URL is resolved once; every address is checked, including IPv4 hidden in IPv6 (mapped, 6to4, Teredo, NAT64). The connection is pinned to the checked IP, so DNS rebinding cannot redirect it. Only ports 80/443, proxies from the environment ignored, redirects re-validated, a total deadline per fetch, a byte cap (HTML stops at 2 MiB), and a byte budget per research run. |
| ADR-008 | Treat user-provided PDFs differently from web claims. | Implemented | A local PDF is accepted as user-selected material; web research is quote-verified. The UI must not describe locally uploaded material as independently verified. |
| ADR-009 | Add HTML source ingestion alongside PDFs. | Implemented | Public search results can be saved as HTML snapshots and text is extracted for claim/evidence review. PDF links are collected and ingested alongside those pages. |
| ADR-010 | Prefer cross-origin corroboration to a Bloom filter for correctness. | Implemented | A Bloom filter only answers a probabilistic membership question; it cannot establish whether a statement is correct. Chroma retrieval checks existing memory first. On web research, independence is counted by registrable domain (eTLD+1, offline Public Suffix List), so `www.example.com` and `example.com`, or two subdomains of one site, count once; hosts under an unknown suffix also count once. Re-verification recomputes this from the stored URLs. |
| ADR-011 | Store conflicts rather than force a consensus. | Implemented | Conflicts are retained in the topic audit record and excluded from normal retrieval unless a direct, quote-verified PDF supports the claim and no collected PDF contradicts it. |
| ADR-012 | Let a direct, quote-verified PDF act as a documentary tie-breaker, not automatic authority. | Implemented | A PDF can still be secondary or incorrect. It resolves a captured conflict only with direct quoted support, independent support from at least two origins, and no opposing PDF evidence. |
| ADR-013 | Preserve original-language text and label model glosses. | Approved for vNext | Sanskrit, Hindi, and other source text must be retained verbatim. A model translation or interpretation is auxiliary, must be labeled, and should not become a factual conclusion without corroboration or human review. |
| ADR-014 | Make web research opt-in on query misses. | Implemented | The UI offers an explicit research-on-miss checkbox. When selected, the app queries memory first, researches only when it returns no supported answer, and retries once. |
| ADR-015 | Fail closed on validation failure. | Implemented | A fetch, parse, LLM output, quote match, or corroboration failure means the claim is not answerable. Retrieval trusts a local PDF only with an explicit `origin=local_pdf`; missing/unknown origins are excluded. Malformed evidence cannot be emitted as API source evidence. |
| ADR-016 | Use indexed topic metadata before semantic search and time archive stages separately. | Implemented | Exact-topic claims can be read from Chroma without an embedding-model load. Other questions still use vector search. JSON audit records remain human-readable but cannot bypass the cleared searchable index; source rechecks and answer generation are shown as separate potentially slow stages. |
| ADR-017 | Stage PDF uploads and show stored versus indexed counts separately. | Implemented | Each file in an upload batch must produce searchable text before any is promoted; failed attempts remove only their newly created files. The UI shows Chroma-indexed PDF sources separately from PDF copies on disk, so older unindexed copies or an intentionally cleared index are not mistaken for searchable documents. |
| ADR-018 | Run research as an in-process background job. | Implemented | `POST /api/research/jobs` returns at once; a bounded worker pool runs jobs (`RESEARCH_MAX_CONCURRENT_JOBS`, queue limit `RESEARCH_MAX_QUEUED_JOBS`), one per topic at a time. Clients follow a replayable event stream and can reconnect without restarting work; `DELETE` cancels between stages and model calls, and every run has a deadline. Jobs live in memory, which is acceptable only because the API runs as one process (ADR-022). |
| ADR-019 | Fingerprint the index with its embedding configuration. | Implemented | Each collection records the embedding provider, model, and chunker that built it. A different embedding model is refused with a rebuild instruction, because mixing vector spaces silently corrupts search. An older or differently chunked index is reported as "rebuild recommended". Local chunks are sized to the embedding model's input limit (all-MiniLM-L6-v2 reads 256 tokens), so no chunk text is silently truncated. Rebuilds are built beside the live collection and swapped in only on success. |
| ADR-020 | Store source snapshots by content and cache their text. | Implemented | Snapshot file names include a hash of their bytes and are never rewritten, so evidence keeps pointing at exactly what it was verified against; each evidence item records the snapshot's SHA-256 and a mismatch fails closed. Extracted text is cached in memory and in a `.txt` sidecar, so re-verifying quotes does not re-parse PDFs on every question. |
| ADR-021 | Batch cross-checks and treat source text as untrusted data. | Implemented | One model call judges up to six candidate claims against one source, cutting calls from claims × sources (up to 60) to about 10 per run; extraction and cross-checks run with bounded parallelism (`LLM_CONCURRENCY`). Source text is wrapped in `<source_text>` tags it cannot close, and prompts say its contents are evidence, not instructions. The source a claim was extracted from may count toward its support because extraction and judgment are separate calls and every quote is verified verbatim; corroboration still needs a second, independent registrable domain. |
| ADR-022 | Run exactly one API process per data directory. | Implemented | Audits, snapshots, uploads, jobs, rate limits, and the LLM budget are process-local. The API takes an exclusive OS lock on `SPYMONK_DATA_DIR` at startup and a second process refuses to start. Horizontal scaling would need shared storage (object storage plus a database) and a shared job queue; that is a deferred decision. |
| ADR-023 | Cap spend and request rates in the API. | Implemented | Per-client token buckets limit research, questions, uploads, and maintenance; a process-wide daily ceiling limits chat-model calls (`LLM_DAILY_CALL_LIMIT`). Limits return 429 with `Retry-After`. Counters reset when the process restarts. |
| ADR-025 | Save what a degraded run fully verified; never let a failure remove memory. | Implemented | A malformed extraction reply is retried once (timeouts and provider errors are retried by the LLM client). A malformed batched cross-check reply is split into one call per claim rather than resent, since an identical prompt was observed to reproduce the identical broken JSON. A claim whose own check still fails is held back as `incomplete`, because a missed check could have hidden a contradiction; fully checked claims are saved. A run with any failure adds claims but never deletes indexed ones, and keeps earlier verified claims it did not re-check. A run that verifies nothing changes no audit or index entry and records an unanswered question (ADR-026). Replaces the first-pass rule that discarded the whole run on any single failure. |
| ADR-026 | Record questions research could not answer, with a report for the asker and a log for developers. | Implemented | A run that verifies no claim (including no search results or no readable source) is a normal outcome, not an error: the UI says "We cannot verify the claims for providing you the answers of your question." No topic audit or index entry is written, so empty topics no longer clutter the archive. One JSON record per run goes to `memory/unanswered/`, holding a plain-language analysis (reason, steps, claims found, sources, next steps) and a developer section (configuration, timings, every model call, verdicts, automatic diagnostics). Records hold claims and short quotes but no prompts, full source text, secrets, or provider error text. They replace the count-only `memory/attempts/` record, which had deliberately stored no claim content. |
| ADR-027 | Render PDF reports in the API with fpdf2. | Implemented | Reports are rendered on demand from the stored record, so they always match the run and need no file storage. fpdf2 is pure Python, and with uharfbuzz it shapes Devanagari correctly, which matters for Sanskrit and Hindi topics. Fonts come from `REPORT_FONT_DIR` or the system; without a Unicode font the report falls back to Helvetica and logs a warning. A browser print-to-PDF flow was rejected because it is not a download and renders differently per browser. |
| ADR-028 | Keep logs with the data, and log every research run. | Implemented | The API log goes to a rotating `logs/spymonk-api.log` as well as the console, so failures can be diagnosed after the terminal is gone. Every research run, not only unanswered ones, writes a developer log (trace plus diagnostics) to `logs/research/`; the newest `RESEARCH_LOG_KEEP` are kept. Only the process holding the data-directory lock writes either, so tests and imports never touch them. |
| ADR-029 | Answer the question when research saves claims. | Implemented | A research run used to end at "Save findings": the claims were stored, but no answer was composed unless the archive already had one, so a successful run showed claims without an answer. The job now answers from the claims it just saved (final step "Answer from new evidence"). Because the claims are already stored, a model failure or cancellation at this step skips only the answer. The ask route reuses this answer instead of making a second model call. |
| ADR-030 | Host for free on Hugging Face Spaces, with the archive backed up to a private dataset. | Implemented | Free Spaces give 2 vCPU and 16 GB RAM (enough for local embeddings) but a disk that is wiped on every restart. The UI and API ship as one Docker container (no CORS), and the archive's files (audits, unanswered records, PDFs, snapshots, run logs) are restored from a private Hugging Face dataset before the app serves, then copied there every 15 seconds and at shutdown. The index is rebuilt from those files at startup instead of being backed up, because copying a live index is unsafe. A failed restore stops startup rather than running with an empty archive; the backup is never deleted from, and a restore never overwrites local files. Hosted mode requires `APP_API_TOKEN` and hides the API schema. Render's free tier (512 MB RAM) and an Oracle Cloud VM (card verification, server administration) were considered. |
| ADR-024 | Drop weak semantic matches before answering. | Implemented | Retrieval filters ineligible passages inside the vector query, removes duplicate text, and drops matches below `RETRIEVE_MIN_SIMILARITY` (cosine 0.25 for all-MiniLM-L6-v2, where related passages scored 0.44+ and unrelated ones 0.15 or less). An unrelated question returns "not found" without an LLM call. |

## Evidence-status vocabulary

| Status | Meaning | Eligible for normal answers? |
| --- | --- | --- |
| `local_source` | Derived from a user-selected PDF. | Yes, labelled as user-provided. |
| `quote_verified` | A source quote is present in its source. Planned label; not emitted by the current code. | Not by itself for future web claims. |
| `corroborated` | Direct quote evidence from the source and at least one independent origin supports it. | Yes. |
| `pdf_resolved` | A direct documentary PDF quote resolves a documented conflict. | Yes, with provenance. |
| `single_source` | Only one origin supports it. | No; audit only. |
| `incomplete` | Looked corroborated, but a planned cross-check failed, so a contradiction may have been missed. | No; audit only until a later run checks it fully. |
| `conflicted` | Direct source evidence disagrees. | No; audit only. |
| `translation_review` | Original-language text needs qualified translation review. Planned with ADR-013; not emitted by the current code. | No, unless separately corroborated. |
